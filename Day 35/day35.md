🧩 Day 27 of #ABTalksAIChallenge — Prompt Puzzle: Master AI Prompting Through Play

We spend so much time teaching people what to build with AI, and almost no time teaching them how to talk to it. So today I built the thing I wish existed when I started prompting: a game that makes bad prompts fail visibly, instead of just quietly returning mediocre output.

What I Built 🧩
✅ A single-file HTML prompt-training game — zero dependencies, works fully offline
✅ 6 randomized coding scenarios (refactoring, unit tests, API design, SQL optimization, bug explanations, commit messages)
✅ 3 distinct challenge types: Build the Prompt (drag-and-drop), Clean the Prompt (spot the junk), Choose the Best Prompt (weak vs. optimized vs. over-engineered)
✅ Live scoring across Accuracy, Time, Moves, Wrong Placements, Hints Used, and an Optimization Bonus
✅ A full Prompt Performance Report — Score, Rank, "Prompt DNA" visualization, personalized feedback, and next milestone
✅ Fully replayable with new randomized scenarios every round

Key Insight 💡
The hardest skill in prompting isn't writing more — it's knowing where the line sits between "not enough context" and "so much context the model drowns in it." That's why every scenario ships with a Weak Prompt, an Optimized Prompt, AND an Over-Engineered Prompt side by side. Watching people confidently pick the over-engineered one — because it sounds more professional — taught me more about prompt design than any tutorial could. Precision beats verbosity, every single time.

What's Next 🔜
Testing whether the same engine holds up for non-technical domains — marketing copy, data analysis, business strategy — where "good prompting" looks completely different.

Sixty days in, the pattern keeps repeating: the projects that teach me the most are never the flashiest ones. They're the ones that force me to make the invisible rules of good prompting visible enough for someone else to feel them.
