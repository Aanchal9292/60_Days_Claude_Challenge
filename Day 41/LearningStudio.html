📦 Module 1: Foundations — Variables, Data Types & Operations

Building blocks of every JavaScript program.

🧠 Variables: let, const, and var

Variables are containers for values. Use let for values that change, const for values that don't, and avoid var (legacy).

let age = 25; // can be reassigned const birthYear = 1998; // cannot be reassigned var old = "deprecated"; // avoid
💡 Analogy: Variables are like labeled boxes. let lets you swap contents, const is a sealed box — you can't change what's inside, but you can modify the object itself (more on that later).

🔢 Primitive Data Types

  • string — text: "hello"
  • number — integers & floats: 42, 3.14
  • boolean — true / false
  • undefined — declared but not assigned
  • null — intentional empty value
  • symbol — unique identifier (advanced)

Use typeof to check a value's type.

typeof "hello"; // "string" typeof 42; // "number"

✅ Number

  • Integers: 1, 100
  • Floats: 3.14, 0.5
  • NaN (not-a-number) is also a number!

✅ String

  • Single quotes: 'hi'
  • Double quotes: "hi"
  • Backticks: `hi ${name}`

⚡ Operators & Type Coercion

JavaScript is loosely typed, which means it automatically converts types when needed — this is coercion.

"5" + 2; // "52" (string concatenation) "5" - 2; // 3 (coerced to number) 5 + true; // 6 (true → 1)

Be careful! Use === (strict equality) to avoid unexpected coercion.

== (loose)

  • 5 == "5" → true
  • 0 == false → true

=== (strict)

  • 5 === "5" → false
  • 0 === false → false

⚠️ Common Misconception

"JavaScript is a compiled language." — No, it's interpreted (or JIT-compiled). Variables are hoisted, but let and const are in a "temporal dead zone" until declaration.

🔑 Key Takeaways

  • Use const by default, let when reassigning.
  • JavaScript has 7 primitive types (string, number, boolean, undefined, null, symbol, bigint).
  • Coercion can be tricky — use === for safety.

⚙️ Module 2: Functions & Control Flow

Reusable logic and decision-making.

🧩 Function Declarations & Expressions

Functions are reusable blocks of code. They can take parameters and return values.

// Declaration (hoisted) function greet(name) { return "Hello, " + name; } // Expression (not hoisted) const greet2 = function(name) { return "Hi, " + name; }; // Arrow function (ES6+) const greet3 = (name) => `Hey, ${name}`;
💡 Analogy: Functions are like recipes. You give them ingredients (parameters), follow steps, and get a dish (return value).

🔁 Control Flow: Conditionals & Loops

if, else if, else, switch, and loops (for, while).

if (score >= 90) { grade = "A"; } else if (score >= 80) { grade = "B"; } else { grade = "C"; } for (let i = 0; i < 5; i++) { console.log(i); // 0,1,2,3,4 }

📦 Scope & Hoisting

  • Global scope — accessible everywhere.
  • Function scope — variables declared inside a function are local.
  • Block scope — let and const are block-scoped ({ }).
  • Hoisting — declarations are moved to the top (but not initializations).
console.log(x); // undefined (hoisted, but not initialized) var x = 5; console.log(y); // ReferenceError (TDZ) let y = 10;

🖱️ Module 3: DOM Manipulation & Events

Make web pages interactive.

🌳 The DOM Tree

The Document Object Model is a tree representation of your HTML. JavaScript can traverse and modify it.

Use document.querySelector, getElementById, querySelectorAll to select nodes.

✏️ Manipulating Elements

  • element.textContent — change text
  • element.innerHTML — change HTML (use cautiously)
  • element.style — change CSS
  • element.classList.add/remove/toggle — manage classes
  • document.createElement & appendChild — add new elements
const title = document.querySelector('h1'); title.textContent = "New Title"; title.classList.add("highlight");

🖱️ Events & Listeners

Events are signals that something happened. Use addEventListener to react.

const btn = document.querySelector('#myBtn'); btn.addEventListener('click', (event) => { alert('Clicked!'); console.log(event.target); // the button });

Event delegation: attach a listener to a parent and use event.target to handle children dynamically.

💡 Analogy: Events are like notifications. You subscribe (add listener) to be notified when something happens (click, keypress, etc.).

🚀 Module 4: Asynchronous JavaScript & Fetch

Handle network requests and timed operations.

⏳ Asynchronous Programming

JavaScript is single-threaded but non-blocking. Asynchronous operations (like network requests) run in the background and notify you when done.

💡 Analogy: Async is like ordering food at a restaurant. You don't stand at the counter waiting — you sit, and the server brings it to you when ready.

📞 Promises

A Promise represents a future value. It has three states: pending, fulfilled, rejected.

const promise = new Promise((resolve, reject) => { // async work if (success) resolve("Data"); else reject("Error"); }); promise .then(data => console.log(data)) .catch(err => console.error(err));

⚡ async/await (modern)

Syntactic sugar over Promises. Write asynchronous code that looks synchronous.

async function fetchData() { try { const response = await fetch('https://api.example.com'); const data = await response.json(); console.log(data); } catch (err) { console.error(err); } }

🌐 Fetch API

fetch() makes HTTP requests. It returns a Promise that resolves to a Response object.

  • response.json() — parse JSON body
  • response.text() — get plain text
  • response.status — HTTP status

⚠️ Common Misconception

"async/await blocks the main thread." — No, it allows other tasks to run while waiting. The function is paused, not the whole program.

🔑 Key Takeaways

  • Asynchronous operations prevent blocking.
  • Promises chain with .then() and .catch().
  • async/await is the most readable way to handle async code.
  • fetch is the modern way to make HTTP requests.
